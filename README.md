# AppleBox Website (Frontend)

Static marketing site for **AppleBox Production Services** — film & TVC
production services in Saudi Arabia. Live at **https://www.applebox.sa**.

No framework: hand-written HTML, CSS, and vanilla JavaScript, served from
**Vercel**. The only build step is `build.js`, a dependency-free script that
generates one real HTML document per route (see "Pages / routing" below).

## Structure

```
applebox-site/
├── index.html          # Source of truth — all sections in one document
├── build.js            # Generates the per-route HTML files + sitemap.xml
├── vercel.json         # cleanUrls / trailingSlash config
├── about.html          # ┐
├── services.html       # │ GENERATED by build.js — do not edit by hand.
├── fleet.html          # │ Each is index.html with that section pre-activated
├── projects.html       # │ and its own <title>/description/canonical.
├── contact.html        # ┘
├── styles.css          # Main stylesheet
├── styles-rtl.css      # RTL/Arabic styles (see "Bilingual" note below)
├── script.js           # Routing, gallery, contact form, BTS carousel, etc.
├── robots.txt          # Points crawlers at the sitemap
├── sitemap.xml         # GENERATED by build.js — all six URLs
├── files/              # Downloadable company profile
└── pages/              # All media (images, video, brochures, fonts, logos)
    ├── homepage/        ├── aboutpage/    ├── servicepage/
    ├── projectpage/     ├── fleets/       └── brandimage/
```

## Pages / routing

Every section has a real, shareable URL:

| URL         | Served file      | Section       |
|-------------|------------------|---------------|
| `/`         | `index.html`     | `page-home`     |
| `/about`    | `about.html`     | `page-about`    |
| `/services` | `services.html`  | `page-services` |
| `/fleet`    | `fleet.html`     | `page-fleet`    |
| `/projects` | `projects.html`  | `page-projects` |
| `/contact`  | `contact.html`   | `page-contact`  |

A direct visit or refresh on any of these returns **HTTP 200** with that
section already active in the served markup — no JavaScript required to see
the right content, which is what makes the inner pages indexable.

In-site clicks stay client-side: a delegated handler in `script.js` intercepts
plain left-clicks on same-origin route links, calls `showPage()` and pushes the
real path. Middle-click, ⌘/Ctrl-click and crawlers follow the href normally.
Back/forward is handled via `popstate`. Legacy `/#fleet`-style links are
upgraded to `/fleet` on load.

> **⚠️ After editing `index.html`, run `node build.js`.**
> The five route files are copies of `index.html`; without a rebuild they will
> serve stale content. The script fails loudly if `index.html` changes shape in
> a way it no longer recognises.

Route titles and descriptions live in **two** places that must stay in sync:
`ROUTES` in `build.js` (written into the served HTML) and `ROUTES` in
`script.js` (applied during client-side navigation).

## Contact form

The form posts JSON to the backend mailer:

```
POST https://applebox-backend.onrender.com/send-email
```

(See `applebox-backend/` for the server.) A hidden honeypot field
(`companyWebsite`) traps bots both client- and server-side.

## SEO

- `sitemap.xml` lists all six URLs and is regenerated by `build.js`.
- Each route document carries its own `<title>`, `<meta name="description">`,
  `<link rel="canonical">`, `og:title`/`og:description`/`og:url` and
  `twitter:title`/`twitter:description`.
- `index.html` includes a JSON-LD `LocalBusiness` schema, Open Graph, and
  Twitter Card tags. Keep these in sync if contact details or social links change.
- After changing `robots.txt`/`sitemap.xml`, re-submit the sitemap in Google
  Search Console.

## Bilingual (Arabic) — currently inactive

`script.js` ships a full EN/AR translation dictionary and `styles-rtl.css`
contains RTL styles, but **no language toggle is wired into the UI** and most
visible strings are not yet tagged with `data-i18n`. The site renders in English
only. To enable Arabic later: add a language toggle button (`.lang-btn[data-lang]`),
tag all visible strings with `data-i18n`, and verify RTL layout.

## Deployment (Vercel)

The site is served by Vercel (`server: Vercel` on the live response) from the
repository root. `vercel.json` sets:

```json
{ "cleanUrls": true, "trailingSlash": false }
```

`cleanUrls` is what lets `/about` serve `about.html`, and it 308-redirects
`/about.html` → `/about` so each page has exactly one canonical URL.

Because the route files are committed, no build command is configured on
Vercel — it stays a zero-config static deploy. **Run `node build.js` and commit
the result whenever `index.html` changes.**

Unknown paths still return a genuine 404; there is no catch-all rewrite.
